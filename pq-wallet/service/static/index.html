TX_C and TX_R (conceptual)

        
    
          
  1. Normal transaction — You create and sign a Dogecoin transaction the same way as today.
    2. 
          
  2. TX_C — commitment — A short fingerprint of the quantum-safe signature is placed in an OP_RETURN (the commitment).
    3. 
          
  3. Optional carrier — A tiny output (for example 1 DOGE) can carry the flow; TX_R spends it to reveal the full PQ public key and signature on-chain, returning funds minus fees.
    4. 
          
  4. Testing — Often the commitment alone is enough; the carrier step is optional.
    5. 
        

        
See libdogecoin PR #294 for PQC carrier support, liboqs integration, and Raccoon-G.

      

      

        
libdogecoin in this pup

        
The Nix build compiles libdogecoin with USE_LIBOQS=ON (Falcon-512, Dilithium2). Tools on PATH: such, sendtx, spvnode. SPV/SMPV use the same code as src/spv.c / src/smpv.c.

      

    


    

      

        
SPV status (same tab as wallet)

        
Use Refresh SPV status on the Wallet tab, or GET /api/spv/status.

      

      

        
Mempool (MemeTracker)

        
If you run the MemeTracker pup, set MEMETRACKER_BASE_URL to its HTTP URL. This wallet can ping health and call /track/<your address> so mempool gossip sees transactions paying you.

        
        
        

      

      

        
Confirmations (explorer)

        
Optional: set EXPLORER_TX_API to a URL containing {txid}, for example Blockchair’s Dogecoin transaction dashboard path. This is not libdogecoin SPV — it is a practical confirmation hint.
