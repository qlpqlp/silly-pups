Admin documentation

Operational runbook for secure deployment and maintenance.

Baseline setup

  • Set QE_ADMIN_TOKEN to a strong random value.
  • Use QE_ADMIN_ALLOWLIST for office/VPN IP access.
  • Set NETWORK and PUBLIC_PORT correctly.
  • Keep QE_CORE_INDEXER_AUTO_START=1 for unattended indexing when Core RPC is set.

Core indexing

  • Set QE_POSTGRES_URL for production backend.
  • Configure Core RPC URL/user/password.
  • Tune: QE_CORE_INDEXER_AUTO_START, QE_CORE_BACKFILL_BATCH, QE_CORE_START_HEIGHT.
  • Monitor via /api/admin/<TOKEN>/core-indexer/status.
  • PQ Phase-1 validation uses canonical commitment output: 6a24 + FLC1/DIL2/RCG4 + 32-byte commitment.
  • Carrier TX_R parsing verifies SHA256(pubkey||signature) against matched TX_C commitment when payload is present in the same block.

Public API security

  • Protect endpoints with token + allowlist policy in Access panel.
  • Use per-user tokens in client JSON for traceability.
  • Harden with rate limits (QE_PUBLIC_RATE_LIMIT, QE_PUBLIC_RATE_WINDOW_SEC).

Service controls

  • Core indexer controls backfill/search ingestion.
  • Validate after actions using Status + Diagnostics panels.

Troubleshooting flow

  • Check /healthz and /readyz.
  • Inspect diagnostics JSON for Core RPC and indexer state.
  • Review Core RPC and indexer diagnostics state.
  • Verify Postgres and Core RPC credentials/network.
