Admin documentation

Operational runbook for secure deployment and maintenance.

Baseline setup

  • Set QE_ADMIN_TOKEN to a strong random value.
  • Use QE_ADMIN_ALLOWLIST for office/VPN IP access.
  • Set NETWORK and PUBLIC_PORT correctly.
  • Keep QE_CORE_INDEXER_AUTO_START=1 for unattended indexing when Core RPC is set.

Core indexing

  • Set QE_POSTGRES_URL for production backend.
  • Embedded Postgres on low-RAM devices: keep QE_POSTGRES_MAX_OPEN_CONNS modest (default 8); add swap or use an external DB if the host OOM-kills postgres.
  • Configure Core RPC URL/user/password.
  • Tune: QE_CORE_INDEXER_AUTO_START, QE_CORE_BACKFILL_BATCH, QE_CORE_START_HEIGHT.
  • Large getblock JSON: raise QE_CORE_RPC_MAX_RESPONSE_MB (default 256), QE_CORE_INDEXER_RPC_TIMEOUT_MS (default 300000), and QE_CORE_INDEX_HEIGHT_TIMEOUT_SEC (default 180).
  • Optional auto-recovery: QE_CORE_INDEXER_AUTO_REWIND_BLOCKS (e.g. 500) rolls back that many heights from Postgres after 5 consecutive RPC stalls at the same block.
  • Manual rewind (indexer stopped): POST /api/admin/<TOKEN>/core-indexer/rewind?from_height=<n> removes indexed rows from height n onward.
  • Monitor via /api/admin/<TOKEN>/core-indexer/status.
  • PQ Phase-1 validation uses canonical commitment output: 6a24 + FLC1/DIL2/RCG4 + 32-byte commitment.
  • Libdogecoin PQC tooling (Falcon-512, TX_C/TX_R, such commands): doc/tools.md § Falcon-512 PQC.
  • Carrier TX_R verification matches SHA256(pubkey||signature) to indexed TX_C Phase-1 OP_RETURN commitments within QE_PQ_CARRIER_COMMITMENT_LOOKBACK_BLOCKS (default 750000) below the TX_R block, plus same-block txs.

Public API security

  • Protect endpoints with token + allowlist policy in Access panel.
  • Use per-user tokens in client JSON for traceability.
  • Harden with rate limits (QE_PUBLIC_RATE_LIMIT, QE_PUBLIC_RATE_WINDOW_SEC).

Service controls

  • Core indexer controls backfill/search ingestion.
  • Database: POST /db/optimize, GET /db/export, POST /db/import, POST /db/query (under /api/admin/<TOKEN>/).
  • Validate after actions using Status + Diagnostics panels.

Troubleshooting flow

  • Check /healthz and /readyz.
  • Inspect diagnostics JSON for Core RPC and indexer state.
  • Review Core RPC and indexer diagnostics state.
  • Verify Postgres and Core RPC credentials/network.

Core indexer controls and PostgreSQL runtime status.

Core backfill indexer

If indexing stalls on a block (RPC timeouts / truncated JSON), stop the indexer, set from_height to the block where you want Postgres cleared from, then rewind and start again.

Core start block

Submit checks PostgreSQL first. If the block already exists, it will not re-index duplicates and only continues adding missing/new blocks.

PostgreSQL database

Optimize runs VACUUM (ANALYZE) (can take a long time). Export streams a pg_dump -Fc archive. Import stops the core indexer (if enabled), then runs pg_restore for custom-format dumps or psql -f for SQL text. Server needs client tools on PATH.
